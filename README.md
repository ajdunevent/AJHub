# AJHub

Signed Flatpak repository for AJ's apps, hosted on GitHub Pages.
The landing page is https://ajdunevent.github.io/AJHub/.

## Using it

```
flatpak remote-add --user --if-not-exists ajhub https://ajdunevent.github.io/AJHub/index.flatpakrepo
flatpak install --user ajhub <app ID>
```

Or install one app directly from its `.flatpakref` file, for example
`https://ajdunevent.github.io/AJHub/net.dunevent.Ripples.flatpakref`.

## How it works

`publish.yml` downloads the latest release bundles of every app listed in
`apps.txt`, imports them into a fresh OSTree repository, signs it, and deploys
it to Pages. Only the newest version of each app is kept. It runs every six
hours, on manual dispatch, when an app's release workflow triggers it, and when
`apps.txt` or the scripts change.

`scripts/generate-site.py` then builds the landing page and the table above.
Descriptions come from each project's GitHub repository description, versions
from its latest release, and icons from the app itself.

Adding an app: add a line to `apps.txt` (`owner/repo AppName`). The app's
releases must include `<AppName>-<arch>-latest.flatpak` assets, which the
shared release workflow produces.

## One-time setup

1. Settings > Pages > Source: GitHub Actions.
2. Create the signing key (no passphrase, used only by this workflow):

   ```
   gpg --batch --quick-generate-key --passphrase '' "Dunevent Flatpak Repository" rsa4096 sign never
   gpg --list-secret-keys --keyid-format long
   gpg --armor --export-secret-keys <FINGERPRINT>
   ```

3. Settings > Secrets and variables > Actions > New repository secret:
   `GPG_PRIVATE_KEY`, containing the full armored output of the last command.
4. Back up the private key somewhere safe. Replacing it later means every user
   must re-add the remote.
5. Actions > Publish > Run workflow.
